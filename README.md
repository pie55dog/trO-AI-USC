# trO-AI-USC

Tro: a networking bracelet for Trojans. Tap bracelets to connect, keep your phone in your pocket, and get one email the next morning with everyone you met.

- [`backend/`](backend/README.md): FastAPI API (LinkedIn sign-in, onboarding, bracelet assignment and uploads, post-event email)
- [`frontend/`](frontend/README.md): mobile web app (sign-up, preferences, tutorial, event dashboard) and the organizer console at `/organizer` (event setup, registration, check-in, summary emails)
- [`firmware/`](firmware/README.md): the bracelet (Seeed XIAO ESP32-S3): ESP-NOW tap detection, live pairing through the backend, LEDs, button

## Live deployment

Everything runs on free plans with no card. Full setup steps and limits are in [`deploy/README.md`](deploy/README.md).

| Piece | Where it lives | Address |
|---|---|---|
| Phone app | GitHub Pages, built by `.github/workflows/pages.yml` on every push to `main` that touches `frontend/` | https://pie55dog.github.io/trO-AI-USC/ |
| Backend API | Render free web service `tro-api`, defined in `render.yaml` | https://tro-api.onrender.com (check: [`/health`](https://tro-api.onrender.com/health), API docs: [`/docs`](https://tro-api.onrender.com/docs)) |
| Database | Render free Postgres `tro-db` | Only reachable from `tro-api` |
| Email | Google Apps Script web app (`deploy/email-relay.gs`) in the tro.at.usc Gmail | URL and key are only in Render's Environment tab |
| Keep-awake ping | `.github/workflows/keep-awake.yml`, every 10 minutes | Pings `/health` |

How the pieces connect:

- The phone app reads the backend address from the repo variable `VITE_API_URL`
  (Settings > Secrets and variables > Actions > Variables). Change it there and re-run
  **Actions > Deploy web app to GitHub Pages** to point the app somewhere else.
- Render redeploys `tro-api` on every push to `main`. Each redeploy restarts the server,
  so don't push during a demo.
- The backend sends email by posting to the Apps Script, which sends from the Gmail account
  that deployed it (about 100 recipients a day). The shared key is set in two places: the
  `RELAY_KEY` line in the script and `EMAIL_RELAY_KEY` on Render. Change both together.
- Organizer and bracelet keys (`ADMIN_API_KEY`, `BRACELET_API_KEY`) were generated by Render
  and are in **tro-api > Environment**. Share them privately, never in the repo.
- LinkedIn sign-in is not used. Its two Render settings are left blank.

Things to remember:

- The free backend sleeps after 15 idle minutes and takes up to a minute to wake. The
  keep-awake ping handles this; open the app a couple of minutes before a demo anyway.
- **The free database deletes itself 30 days after it was created (around December 15, 2026).**
  Export anything you want to keep before then (Render's database page has the `pg_dump` details).
- After the hackathon, turn off **Actions > Keep backend awake > ... > Disable workflow**.

## Run it locally instead

Run everything on a laptop and open it from a phone on the same Wi-Fi:

```
./scripts/local-server.sh      # prints the link to open on the phone
./scripts/send-summaries.sh    # sends the summary email to everyone who signed up
```

The first run creates `backend/.env`. Emails are saved to `backend/media/outbox`
until you run `./scripts/setup-email.sh`. It asks for the address you want trO to
send from and an app password (typed in Terminal, never into a chat), tests the
login, saves it to `backend/.env`, and sends a confirmation email. Then restart
the server.
